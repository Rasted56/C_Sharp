Консультация 7. Методы и параметры

Объявление и вызов методов, void, ref/out, params, необязательные аргументы, перегрузка, рекурсия

Цели консультации

К концу занятия слушатель должен:

  • Пониматьзачем нужны методы и что такое «декомпозиция»
  • Уметьобъявлять и вызывать методы, возвращать значения, использовать void
  • Различатьпараметры по значению и по ссылке (ref, out), понимать params
  • Пониматьперегрузку методов и правила её разрешения
  • Знатьобласти видимости и время жизни переменных
  • Иметь представлениео рекурсии и уметь написать простой рекурсивный метод

1. Зачем нужны методы

Метод — именованный блок кода, который можно вызывать многократно и который решает одну задачу. Причины использовать методы:

  • DRYустранение дублирования
  • ЧитаемостьCalculateTotal(items) понятнее, чем 20 строк внутри Main
  • Декомпозициябольшая задача разбивается на маленькие
  • Тестируемостьметод с чёткими входами/выходами легко проверить
  • Повторное использованиев том числе в других проектах
Правило, которое стоит проговорить: метод должен делать одну вещь и иметь понятное имя (глагол: Calculate, Print, Find). Если метод не помещается на экран или в нём несколько «этапов» — скорее всего, его пора разбить.

2. Объявление и вызов

Общий вид:

[модификатор] возвращаемыйТип Имя(параметры) { // тело return значение; // если тип не void }

Простой пример:

static int Add(int a, int b) { return a + b; } // вызов int sum = Add(2, 3); // 5 Console.WriteLine(Add(10, 20));

Разбор:

  • staticметод принадлежит классу, а не объекту (на базовом уровне все методы в Program — static; подробно про static/instance — на теме ООП)
  • intвозвращаемый тип
  • Addимя (PascalCase)
  • (int a, int b)параметры: тип + имя
  • returnвозвращает значение и завершает метод

Вызов: имя + аргументы в скобках. Аргументы должны соответствовать параметрам по типу, количеству и (обычно) порядку. Количество и типы проверяет компилятор — это одна из сильных сторон C#.

3. void — метод без возвращаемого значения

static void PrintGreeting(string name) { Console.WriteLine($"Привет, {name}!"); } PrintGreeting("Анна");

Особенности:

  • returnможно использовать для досрочного выхода, но без значения: if (name == null) return;
  • Выражениеvoid-метод нельзя использовать в выражении (int x = PrintGreeting(...) — ошибка)
  • Стильесли метод «ничего не возвращает, но что-то делает» (печатает, сохраняет) — это нормально; но методы, которые и считают, и печатают, — плохой стиль (смешение ответственности)

4. Параметры и аргументы: по значению

По умолчанию параметры передаются по значению — в метод попадает копия:

static void TryChange(int x) { x = 100; // меняем копию } int a = 5; TryChange(a); Console.WriteLine(a); // 5 — оригинал не изменился

Для значимых типов (тема 2) — копируется значение; для ссылочных — копируется ссылка, поэтому изменения внутри объекта видны снаружи, а переприсваивание ссылки — нет:

static void FillArray(int[] arr) { arr[0] = 999; // меняем содержимое — видно снаружи arr = new int[10]; // переприсваивание ссылки — не видно } int[] data = { 1, 2, 3 }; FillArray(data); Console.WriteLine(data[0]); // 999
Это ключевой момент темы — стоит показать оба случая.

5. ref и out — передача по ссылке

Когда нужно, чтобы метод изменил переменную вызывающего кода, используют ref или out.

ref — переменная должна быть инициализирована до вызова, метод может читать и писать

static void Increment(ref int x) { x++; } int n = 5; Increment(ref n); Console.WriteLine(n); // 6

out — переменная не обязана быть инициализирована до вызова, но метод обязан присвоить ей значение до возврата

static bool TryDivide(int a, int b, out int result) { if (b == 0) { result = 0; return false; } result = a / b; return true; } if (TryDivide(10, 2, out int res)) Console.WriteLine(res); // 5
Связь с предыдущими темами: int.TryParse — тот же паттерн «bool + out», который мы уже использовали в темах 2 и 5. Теперь видно, как он устроен «изнутри» — хороший момент для «ага-эффекта».

Правила:

  • Указаниеref/out указываются и при объявлении, и при вызове (Increment(ref n), TryDivide(..., out int res))
  • Объявление в вызовеout-параметр можно объявить прямо в вызове (out int res) — C# 7+
  • Читаемостьref/out — мощный инструмент, но злоупотребление ухудшает читаемость; если метод возвращает несколько значений, часто лучше вернуть кортеж ((int min, int max)) (упомянуть, не углубляться)

6. params — переменное число аргументов

Позволяет передать произвольное количество аргументов одного типа:

static int Sum(params int[] numbers) { int total = 0; foreach (int n in numbers) total += n; return total; } Console.WriteLine(Sum(1, 2)); // 3 Console.WriteLine(Sum(1, 2, 3, 4, 5)); // 15 Console.WriteLine(Sum()); // 0

Правила:

  • Позицияparams — только последний параметр
  • Внутриобычный массив
  • Массивможно передать и готовый массив: Sum(new[] { 1, 2, 3 })

7. Необязательные параметры и именованные аргументы

Параметры по умолчанию (необязательные) — задаются в объявлении:

static void Print(string text, bool upper = false) { Console.WriteLine(upper ? text.ToUpper() : text); } Print("привет"); // привет Print("привет", true); // ПРИВЕТ Print("привет", upper: true); // именованный аргумент

Правила:

  • Порядокнеобязательные параметры идут после обязательных
  • Значенияпо умолчанию — константы (или default)
  • Именованныеаргументы позволяют передавать в любом порядке и повышают читаемость при многих параметрах: CreateUser(name: "Анна", age: 25)

8. Перегрузка методов

Перегрузка (overload) — несколько методов с одним именем, но разными сигнатурами (типами/количеством параметров):

static int Max(int a, int b) => a > b ? a : b; static double Max(double a, double b) => a > b ? a : b; static int Max(int a, int b, int c) => Max(Max(a, b), c);

Компилятор выбирает подходящую версию по аргументам. Правила:

  • Сигнатура= имя + типы параметров (порядок и количество); возвращаемый тип не входит в сигнатуру
  • Только возвратнельзя перегрузить только по возвращаемому типу — ошибка компиляции
  • Смыслперегрузки должны различаться смыслом, а не «на всякий случай»; иначе код трудно читать
Показать, что перегрузка — это то, чем мы уже пользуемся: Console.WriteLine имеет десятки перегрузок под разные типы. Хороший «ага-момент».

9. Область видимости и время жизни

  • Локальныепараметры и локальные переменные существуют только внутри метода; снаружи недоступны
  • Инициализациялокальная переменная должна быть инициализирована до использования
  • Вложенные блоки{} создают вложенную область; переменная внешнего блока видна во внутреннем, но не наоборот
  • Совпадение имёнимя параметра может совпадать с именем переменной снаружи — это разные переменные (и повод для путаницы, лучше избегать)
Стек вызовов: каждый вызов метода создаёт свой «кадр» с параметрами и локальными; при возврате — уничтожается. Это объясняет, почему изменения локальных переменных не видны снаружи (раздел 4).

10. Рекурсия — кратко

Рекурсия — метод вызывает сам себя. Обязательны:

  • Базовый случайусловие остановки
  • Шагприближение к базовому случаю
static int Factorial(int n) { if (n <= 1) return 1; // базовый случай return n * Factorial(n - 1); // шаг }

Классические примеры: факториал, числа Фибоначчи, обход дерева, ханойские башни. Что проговорить:

  • Стекрекурсия элегантна, но каждый вызов — кадр стека; глубокая рекурсия → StackOverflowException
  • Циклчасто рекурсию можно заменить циклом (факториал — легко), и это эффективнее
  • Базовый случайбез базового случая — бесконечная рекурсия и падение
  • Уровеньна базовом уровне достаточно уметь прочитать рекурсивный метод и написать простой (факториал, сумма цифр, Фибоначчи)

11. Практические задания

  • 1Написать методы Add, Subtract, Multiply, Divide и вызвать их; в Divide обработать деление на ноль (вернуть bool + out-результат).
  • 2Метод IsEven(int) и IsPositive(int), использующие return булева выражения в одну строку.
  • 3Метод PrintArray(int[]) для печати массива — вынести повторяющийся вывод из предыдущих заданий.
  • 4Метод TryParsePositiveInt(string, out int) — обёртка над int.TryParse с проверкой > 0.
  • 5Метод Sum(params int[]) и вызов с разным числом аргументов.
  • 6Перегрузки Max(int,int), Max(double,double), Max(int,int,int); проверить, какая версия вызывается.
  • 7Рекурсивный Factorial и рекурсивная SumOfDigits(int); сравнить с итеративной версией.
  • 8Разбить одну из задач темы 5 (например, «угадай число») на методы: GenerateNumber, ReadGuess, CheckGuess.

12. Типичные ошибки и вопросы новичков

  • Забытый returnв методе с возвращаемым типом — ошибка компиляции «не все пути возвращают значение».
  • return в void со значениемошибка.
  • Без ref/outожидание, что метод изменит аргумент без ref/out — частая логическая ошибка (раздел 4).
  • out без присваиваниядо return — ошибка компиляции.
  • ref с неинициализированнойпеременной — ошибка.
  • Только по возвратуперегрузка только по возвращаемому типу — не компилируется.
  • Неоднозначностьперегрузки (Max(1, 2.0)) — компилятор может не выбрать; упомянуть, что бывает.
  • params не последнимошибка.
  • Забыли staticметод не виден из Main без объекта; на базовом уровне все методы — static.
  • Рекурсия без базовогослучая → StackOverflowException.
  • Слишком большой метод«делает всё»; сигнал к декомпозиции.
  • Дублированиекода вместо вызова метода — теряется весь смысл методов.
