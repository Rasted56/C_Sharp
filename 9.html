Консультация 9. Основы ООП: классы, объекты, поля, свойства, методы

Классы и объекты, поля, свойства, конструкторы, инкапсуляция, this и static

Цели консультации

К концу занятия слушатель должен:

  • Пониматьзачем нужно ООП и что такое «модель предметной области»
  • Уметьобъявлять класс и создавать объекты (new), понимать разницу между классом и экземпляром
  • Знатьполя, свойства, методы и конструкторы, уметь их писать
  • Пониматьмодификаторы доступа (public/private) и принцип инкапсуляции
  • Пониматьthis, static и разницу между статическими и экземплярными членами
  • Уметьпроектировать простой класс с валидацией в свойствах

1. Зачем нужно ООП

До этого мы писали «процедурно»: данные отдельно, методы отдельно. Проблемы:

  • Разбросанностьданные и операции над ними разбросаны
  • Целостностьлегко нарушить целостность (кто угодно поменяет поле на недопустимое значение)
  • Расширениетрудно переиспользовать и расширять

ООП позволяет объединить данные и поведение в одном типе — классе, и описать предметную область «как в жизни»: User, Order, Product, Account. Это делает код ближе к задаче и устойчивее к изменениям.

На занятии — только основы: классы, объекты, поля, свойства, методы, конструкторы, инкапсуляция, static. Наследование, полиморфизм, интерфейсы — на следующей консультации.

2. Класс и объект

Класс — это шаблон (чертёж, тип). Объект (экземпляр) — конкретная «вещь», созданная по этому шаблону.

class User { public string Name; public int Age; } // создание объекта var user = new User(); user.Name = "Анна"; user.Age = 25; Console.WriteLine($"{user.Name}, {user.Age}");

Ключевые моменты:

  • Один и многокласс объявляется один раз, объектов может быть много
  • Свои значениякаждый объект хранит свои значения полей
  • newвыделяет память в куче и возвращает ссылку на объект
  • Ссылкапеременная класса — ссылочная (тема 2): var u2 = user; копирует ссылку, а не объект
Стоит сразу показать: u2.Age = 30; изменит и user.Age — тот же объект. Это прямая связь с темой 2 и частый источник ошибок.

3. Поля

Поле — переменная, принадлежащая объекту (или классу, если static). Хранит состояние.

class User { public string Name; // поле public int Age; // поле }

Особенности:

  • По умолчаниюполя класса получают значения по умолчанию (null, 0, false) — в отличие от локальных переменных (тема 2)
  • privateобычно поля делают private, а доступ дают через свойства (раздел 5)
  • Публичные поляплохая практика в большинстве случаев: нельзя проверить значение, нельзя поменять реализацию, не сломав код снаружи
Именование: приватные поля — _name или name (camelCase), публичные — Name (PascalCase). На занятии выбрать один стиль и держаться его.

4. Методы

Метод — поведение объекта. Всё из темы 7 работает и здесь, плюс:

  • Доступметоды имеют доступ к полям и свойствам своего объекта
  • Видимостьмогут быть public (для внешнего мира) или private (внутренние помощники)
class User { private string _name; private int _age; public void SetName(string name) { if (string.IsNullOrWhiteSpace(name)) throw new ArgumentException("Имя не может быть пустым"); _name = name; } public string GetInfo() { return $"{_name}, {_age} лет"; } }
Стиль «Get/Set-методы» — это то, что в C# чаще делают через свойства (раздел 5). Показать оба подхода и объяснить, что свойства — более идиоматичны для C#.

5. Свойства

Свойство — «умное» поле: снаружи выглядит как поле, внутри — методы get и set. Основной способ дать контролируемый доступ к данным.

Автосвойство (когда проверок не нужно)

class Product { public string Title { get; set; } public decimal Price { get; set; } }

Свойство с логикой (валидация, вычисление)

class User { private string _name; public string Name { get => _name; set { if (string.IsNullOrWhiteSpace(value)) throw new ArgumentException("Имя не может быть пустым"); _name = value; } } }

Только для чтения (значение задаётся в конструкторе или вычисляется)

public string FullName { get; } // set только в конструкторе public int Age { get; private set; } // set только внутри класса public bool IsAdult => Age >= 18; // вычисляемое свойство

Ключевые идеи:

  • valueнеявный параметр сеттера
  • Валидациясвойства позволяют валидировать данные при записи — главный аргумент против публичных полей
  • Вычисляемыесвойства (=>) не хранят данные, а считают на лету
  • init(C# 9+) — «установить только при создании»; упомянуть, не углубляться
Практическое правило для слушателей: по умолчанию — автосвойство { get; set; }; если нужна проверка или ограничение доступа — пишем логику.

6. Конструкторы

Конструктор — специальный метод, вызываемый при new. Задаёт начальное состояние объекта и гарантирует, что объект создаётся «валидным».

class User { public string Name { get; } public int Age { get; } public User(string name, int age) { if (string.IsNullOrWhiteSpace(name)) throw new ArgumentException("Имя не может быть пустым"); if (age < 0) throw new ArgumentOutOfRangeException(nameof(age)); Name = name; Age = age; } } var u = new User("Анна", 25); // var bad = new User("", -5); // исключение — объект не создастся

Особенности:

  • Имяимя конструктора = имя класса, без возвращаемого типа
  • Перегрузкаможно иметь несколько конструкторов (перегрузка, тема 7)
  • Делегирование: this(...) — вызов другого конструктора того же класса
  • По умолчаниюесли конструкторов нет — компилятор создаёт конструктор по умолчанию без параметров
  • С параметрамиесли объявлен хотя бы один конструктор с параметрами — конструктор по умолчанию не создаётся автоматически
  • static-конструктордля инициализации статических данных (упомянуть)
Практика: конструктор с обязательными параметрами + свойства только для чтения — надёжный способ гарантировать валидность объекта.

7. Модификаторы доступа и инкапсуляция

Инкапсуляция — скрытие внутреннего устройства и предоставление контролируемого доступа. Реализуется модификаторами:

  • publicдоступно отовсюду
  • privateтолько внутри класса (по умолчанию для членов класса)
  • internalвнутри сборки (проекта)
  • protectedвнутри класса и наследников (тема 10)

Практическая схема «по умолчанию»:

  • Поляprivate
  • Свойства и методынужные снаружи — public
  • Вспомогательныеметоды — private
  • Классpublic (если нужен другим)
class BankAccount { private decimal _balance; // скрыто public decimal Balance => _balance; // только чтение снаружи public void Deposit(decimal amount) { if (amount <= 0) throw new ArgumentOutOfRangeException(nameof(amount)); _balance += amount; } public bool TryWithdraw(decimal amount) { if (amount <= 0 || amount > _balance) return false; _balance -= amount; return true; } }
Снаружи нельзя «сломать» баланс напрямую — только через методы с проверками. Это и есть инкапсуляция. Хороший пример для обсуждения на занятии.

8. this

this — ссылка на текущий объект. Нужен, когда:

  • Совпадение имёнимя параметра совпадает с именем поля/свойства: this.Name = name;
  • Передачапередать текущий объект в другой метод
  • Делегированиевызвать другой конструктор: : this(...)

В большинстве случаев this необязателен, но при совпадении имён — обязателен или полезен для ясности. Главное — не путать: this доступен только в экземплярных членах (не в static).

9. static — статические члены

static — член принадлежит классу, а не объекту. Один на всех.

class Counter { public static int Total; // общее для всех public int Id { get; } public Counter() { Total++; Id = Total; } } var a = new Counter(); // Total = 1, a.Id = 1 var b = new Counter(); // Total = 2, b.Id = 2 Console.WriteLine(Counter.Total); // 2 — обращение через класс

Что важно:

  • Через классстатические поля/методы вызываются через имя класса, а не через объект: Counter.Total, Math.Max(...), Console.WriteLine(...) — всё это static
  • Нет thisв static-методе нет this и нельзя обращаться к экземплярным членам
  • Утилитыстатические методы — для «утилит», не зависящих от состояния объекта
  • Глобальное состояниестатическое состояние — глобальное, требует осторожности (тесты, многопоточность); на базовом уровне — знать, не злоупотреблять
Связать с темой 7: все методы, которые мы писали в Program, были static именно поэтому — мы не создавали объект Program.

10. Класс vs объект: сводка

  • Классшаблон, тип — User
  • Объектэкземпляр класса — new User(...)
  • Поледанные объекта — _name
  • Свойствоконтролируемый доступ к данным — Name { get; set; }
  • Методповедение объекта — GetInfo()
  • Конструкторинициализация при создании — User(string, int)
  • staticпринадлежит классу, один на всех — Counter.Total
Эту таблицу стоит вывести на доске — она помогает уложить тему.

12. Типичные ошибки и вопросы новичков

  • Класс и объектпутаница — «класс — это чертёж, объект — дом».
  • Копирование через =копируется ссылка, а не объект (тема 2).
  • Публичные полянет валидации, нельзя изменить реализацию; использовать свойства.
  • Забыли newUser u; без new даёт null; обращение к членам → NullReferenceException.
  • Свойство только для чтенияно пытаются присвоить снаружи — ошибка компиляции; set только в конструкторе.
  • this в staticв static-методе — ошибка компиляции.
  • static через объектобращение к static через объект — формально можно, но вводит в заблуждение; правильно через класс.
  • Валидация в сеттеребросает исключение — иногда это неудобно; обсудить, что проверка может быть и в конструкторе/методе.
  • Забыли инициализироватьсвойства — объект «полупустой»; конструктор должен гарантировать валидность.
  • Смешение ответственностикласс User, который ещё и печатает, сохраняет в файл и отправляет письма; сигнал к декомпозиции.
  • null-свойствапри обращении к членам null падение; проверять или использовать ?/?? (кратко упомянуть).
