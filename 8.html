Консультация 8. Строки и форматирование

Неизменяемость string, методы строк, StringBuilder, форматирование и культура

Цели консультации

К концу занятия слушатель должен:

  • Пониматьчто string — ссылочный и неизменяемый тип, и какие последствия это имеет
  • Уметьуверенно пользоваться основными методами string (Length, Substring, Split, Replace, Trim, Contains, StartsWith/EndsWith, IndexOf, ToUpper/ToLower)
  • Знатькогда нужен StringBuilder и почему конкатенация в цикле — плохая идея
  • Уметьформатировать значения: интерполяция, string.Format, спецификаторы (F2, D3, P, C, dd.MM.yyyy)
  • Пониматьроль культуры (CultureInfo) и уметь сравнивать строки корректно (StringComparison)

1. Строка — ссылочный и неизменяемый тип

string — ссылочный тип (тема 2), но с важной особенностью: неизменяемый (immutable). Любая «модификация» создаёт новую строку, а исходная остаётся прежней.

string s = "hello"; string t = s.ToUpper(); Console.WriteLine(s); // hello — не изменилось Console.WriteLine(t); // HELLO — новая строка

Что это значит на практике:

  • s += "!"в цикле на каждой итерации создаёт новую строку и копирует старую → квадратичная сложность и лишние аллокации
  • Раздачастроки можно безопасно «раздавать» — их никто не изменит
  • StringBuilderдля сборки длинных строк из кусков есть StringBuilder (раздел 5)
Также стоит проговорить интернирование (на уровне «строковые литералы переиспользуются»), но без углубления — достаточно знать, что == для строк сравнивает содержимое, а не ссылки.

2. Создание строк и основные свойства

string a = "текст"; // литерал string b = new string('x', 5); // "xxxxx" string c = new string(new[] { 'a', 'b' }); // "ab" string empty = string.Empty; // "" — предпочтительнее, чем "" string? maybeNull = null; // null допустим

Основное:

  • Lengthколичество символов (не байт!); для null обращение к Length даёт NullReferenceException
  • s[i]доступ к символу по индексу (только чтение — строку нельзя изменить по индексу)
  • s[^1]последний символ (C# 8+), как у массивов

Проверка на пустоту/null — практический паттерн:

if (string.IsNullOrEmpty(s)) { ... } // null или "" if (string.IsNullOrWhiteSpace(s)) { ... } // null, "" или только пробелы

Это стоит показать сразу — используется постоянно.

3. Основные методы string

Поиск и проверки

s.Contains("abc") // есть ли подстрока s.StartsWith("ab") // начинается с s.EndsWith("bc") // заканчивается на s.IndexOf("b") // индекс первого вхождения (-1, если нет) s.LastIndexOf("b") // индекс последнего вхождения

Извлечение и замена

s.Substring(2) // с индекса 2 до конца s.Substring(2, 3) // 3 символа с индекса 2 s.Replace("a", "b") // заменить все вхождения s.Remove(2) // удалить с индекса 2 до конца s.Insert(2, "XY") // вставить в позицию 2

Обрезка и регистр

s.Trim() // убрать пробелы с обеих сторон s.TrimStart() / s.TrimEnd() s.Trim('*') // убрать конкретные символы s.ToUpper() / s.ToLower()

Разбиение и объединение

"a,b,c".Split(',') // ["a","b","c"] "a b c".Split(' ', StringSplitOptions.RemoveEmptyEntries) string.Join(", ", new[] { "a", "b", "c" }) // "a, b, c"
Важно подчеркнуть: все эти методы возвращают новую строку, исходная не меняется. Replace, Trim и т. п. не «модифицируют на месте».

Split — рабочая лошадка для разбора ввода; RemoveEmptyEntries спасает от пустых элементов при повторных разделителях — частая практическая деталь.

4. Сравнение строк

Ключевое:

  • == и !=для string сравнивают содержимое (перегружены)
  • Культурано по умолчанию — с учётом культуры и регистра, что даёт сюрпризы в некоторых языках
  • StringComparisonдля предсказуемого поведения используйте string.Equals с явным StringComparison
string a = "Admin"; string b = "admin"; Console.WriteLine(a == b); // false (регистр) Console.WriteLine(a.Equals(b, StringComparison.OrdinalIgnoreCase)); // true
Рекомендация: для сравнения «как есть» — StringComparison.Ordinal; без учёта регистра — OrdinalIgnoreCase. Для пользовательских данных (сортировка имён) — CurrentCulture. На базовом уровне достаточно Ordinal/OrdinalIgnoreCase, но знать про культуру — важно.

CompareTo/string.Compare — для сортировки; упомянуть, не углубляться.

5. StringBuilder — когда строк много

Если строку нужно собрать из многих кусков (цикл, построчная сборка), конкатенация через +/+= создаёт новую строку на каждом шаге. Для этого есть StringBuilder:

using System.Text; var sb = new StringBuilder(); for (int i = 1; i <= 5; i++) { sb.Append(i).Append(' '); } sb.AppendLine("готово"); string result = sb.ToString(); // "1 2 3 4 5 готово"

Основные методы: Append, AppendLine, Insert, Remove, Replace, Clear, ToString. StringBuilder изменяемый — операции меняют его внутренний буфер, а не создают новый объект.

Практическое правило для слушателей:
1–3 конкатенации — + или интерполяция, читается лучше;
сборка в цикле / десятки кусков — StringBuilder.

6. Форматирование значений

Интерполяция (основной способ):

int age = 25; double price = 1234.5; DateTime date = new DateTime(2026, 10, 19); Console.WriteLine($"Возраст: {age}"); Console.WriteLine($"Цена: {price:F2}"); // 1234,50 Console.WriteLine($"Дата: {date:dd.MM.yyyy}"); // 19.10.2026 Console.WriteLine($"Код: {age:D3}"); // 025 Console.WriteLine($"Доля: {0.256:P1}"); // 25,6 %

Спецификаторы, которые стоит знать:

  • F2фиксированная точность (2 знака)
  • D3целое с ведущими нулями
  • P1проценты
  • Cвалюта (зависит от культуры)
  • Eэкспонента
  • Nс разделителями разрядов
  • Xшестнадцатеричное
  • DateTimedd.MM.yyyy, HH:mm:ss, yyyy-MM-dd

string.Format — старый, но встречается в чужом коде:

string s = string.Format("Цена: {0:F2}, дата: {1:dd.MM.yyyy}", price, date);
Выравнивание — в интерполяции и Format: {price,10:F2} (ширина 10, по правому краю), {name,-10} (по левому). Пригодится для таблиц (например, таблица умножения из темы 5).

7. Культура и разделители

Одна из самых коварных тем для новичков: разделитель дробной части зависит от культуры. В русской локали — ,, в инвариантной — .

using System.Globalization; double d = 3.14; Console.WriteLine(d.ToString()); // 3,14 (ru-RU) Console.WriteLine(d.ToString(CultureInfo.InvariantCulture)); // 3.14

Проблемы, которые это вызывает:

  • Parsedouble.Parse("3.14") в русской локали может дать 314 или исключение — зависит от культуры
  • Файлы/БД/JSONсохранение чисел в файл/БД/JSON и обратное чтение должно быть в InvariantCulture
  • Пользовательформатирование для пользователя — наоборот, в его культуре
Практические правила:
для ввода/вывода чисел в файлах, API, конфигах — CultureInfo.InvariantCulture (или TryParse с явной культурой);
для показа пользователю — CurrentCulture (по умолчанию);
decimal для денег, double для измерений — напоминание из темы 2.

8. Полезные мелочи

  • string.Concat, string.Joinбыстрее и чище, чем ручная конкатенация.
  • string.IsNullOrWhiteSpaceпочти всегда то, что нужно для проверки пользовательского ввода.
  • s.Split с StringSplitOptionsRemoveEmptyEntries и TrimEntries (C# 8+).
  • s.ToCharArray()когда нужен посимвольный разбор.
  • char.IsDigit, char.IsLetter, char.IsWhiteSpaceдля проверки символов.
  • Интерполяция с выражениями$"{(a > b ? a : b)}" — работает, но не увлекаться.
  • Многострочные строкиverbatim @"..." (без экранирования), raw string literals """...""" (C# 11+) — показать, что есть.

9. Практические задания

  • 1Ввести строку, вывести её длину, первый и последний символ, в верхнем и нижнем регистре.
  • 2Проверить, является ли строка палиндромом (сравнить с перевёрнутой, без учёта регистра и пробелов).
  • 3Посчитать количество слов в предложении (Split + RemoveEmptyEntries).
  • 4Заменить в строке все вхождения одного слова на другое (учесть, что Replace меняет все вхождения).
  • 5Обрезать пробелы и привести к нижнему регистру email-адрес; проверить, содержит ли он @ и ..
  • 6Разобрать строку вида "Иван;25;Москва" через Split(';') и вывести поля по отдельности с подписями.
  • 7Собрать через StringBuilder строку "1, 2, 3, ..., 100"; сравнить с вариантом через += в цикле (обсудить разницу).
  • 8Вывести таблицу товаров (название, цена) с выравниванием и форматированием {name,-15} {price,10:F2}.
  • 9Распарсить "3.14" и "3,14" с InvariantCulture и CurrentCulture; объяснить разницу.

10. Типичные ошибки и вопросы новичков

  • NullReferenceExceptionна s.Length — не проверили null; использовать IsNullOrEmpty/IsNullOrWhiteSpace.
  • Replace/Trimожидание, что Replace/Trim изменят строку — они возвращают новую; нужно присвоить: s = s.Trim();.
  • s[0] = 'X'строку нельзя менять по индексу; ошибка компиляции.
  • Конкатенация в циклеквадратичная сложность; нужен StringBuilder.
  • Split с пустымиэлементами — удивление от "a,,b".Split(','); объяснить RemoveEmptyEntries.
  • ToLower для сравнениясравнение без учёта регистра через ToLower() — работает, но лучше StringComparison.OrdinalIgnoreCase.
  • == для строк«всегда работает» — да, для содержимого, но культура и регистр — источник сюрпризов.
  • double.Parse без культурыпадает или даёт неверный результат в разных локалях; использовать InvariantCulture.
  • Substring за границамиArgumentOutOfRangeException; проверять длину.
  • Length — символыне байты — для кириллицы/эмодзи длина в символах ≠ длине в байтах; для эмодзи есть суррогатные пары (не углубляться, но упомянуть).
  • ToString() для nullдля string? даёт ""? Нет, null.ToString() — падение; для интерполяции null выводится как пустая строка, но прямое обращение — нет.
